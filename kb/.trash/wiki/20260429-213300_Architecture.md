# Architecture

Three architectural shapes have been discussed for ingesting card transaction data into AEP. Each represents a different trade-off between cost, flexibility, and implementation complexity.

## Architectural Options

### Option A: Aggregated Features into AEP (Enriched Batch)

Extend the current pattern. Add more features, push more often. Pre-computed features (spend by category, velocity, dormancy flags) computed in Snowflake and pushed to AEP as audience files via nightly batch connector.

**Pros:** Lowest cost (~$80K/yr incremental), lowest risk, fastest to ship (~8 weeks)
**Cons:** Does not solve the core problem — every new audience is still a Data Eng ticket; AEP profile attribute count has a soft ceiling ~500 cols before perf degrades; 120 features gets halfway there on one domain

**Cost:** ~$80K/yr incremental; ~8 weeks build time

### Option B: Raw Transactions into AEP (Daily Batch)

Stream the daily Snowflake transaction table into AEP as an experience event. Marketing and Analytics can build any feature they want inside AEP without Data Eng cycles.

**Pros:** Solves the backlog problem — self-serve segment authoring on raw events; flexibility to answer questions not yet anticipated; supports all three MVP use cases
**Cons:** $500K–$700K/yr incremental vs. today; profile density risk requires active management; ~16 weeks to ship

**Cost:** $500K–$700K/yr incremental; ~16 weeks build time

**Schema:** 25 fields retained from ~56-field TSYS authorization record. 31 operational fields stripped at ingestion. Fields include: eventId, customerId, accountId, tokenizedPan, timestampAuth, timestampSettle, amountSettle, mcc, mccCluster, merchantName, merchantChainId, transactionType, authResult, disputeFlag, refundFlag, and others.

### Option C: Raw Transactions into AEP (Streaming/Real-Time)

Skip Snowflake, tap the Kafka topic off the authorization stream, land in AEP in near real-time.

**Pros:** Enables triggered journeys at the speed of cardholder behavior; future-proofs for Phase 3+ use cases
**Cons:** ~4x Option B ($2.0M–$2.8M/yr incremental); 24–30 week build; operational complexity (on-call, alerting, replay machinery); no MVP use case requires it

**Cost:** $2.0M–$2.8M/yr incremental; 24–30 weeks build time

**Recommendation:** Do not do for MVP. Revisit Phase 3.

## Decision

Real debate is between Option A and Option B. Option C is a Phase 2 conversation.

Analytics argues for Option B: every time a feature is pre-aggregated before hitting the marketing surface, the team loses the ability to iterate on that feature without another Data Eng cycle. Priya argues for Option A (or A + fast path for new features) given cost concerns.

**Adobe consultant Aisha Patel** noted that both deployments she's worked on ended up hybrid (trimmed events in AEP + Snowflake feature layer continuing to run). Neither went pure event-level at launch, neither stayed pure-feature longer than 18 months.

## Open Scoping Items

- **Profile density:** At 11M transactions/day with 13-month retention — median ~980 events/profile, p90 ~2,400, p99 ~4,200, p99.9 ~11,800. AEP supports ~5,000 events/profile for standard operations; within envelope but not comfortably for batch/segmentation use cases. Two levers: shorter retention (NOT recommended) and same-merchant same-day collapse (reduces 15–25%, recommended as optional MVP toggle pending Analytics input).
- **Identity resolution:** Tokenized PAN is the obvious AEP profile linking key, but needs Infosec confirmation it's stable across card re-issuance.
- **Merchant normalization:** Raw merchant strings are messy; Marketing will get poor audiences without normalization. Waiting for full Merchant Taxonomy project means shipping in 2027. Middle path: curated top-N lookup (top 500-1000 chains) covering 60-70% of volume, scoped in parallel by Linh and Jessica.

## Data Grain Decision

Raw transactions vs. aggregated features is the biggest open question. Key points:

- Priya: 80%+ of use cases are answered by aggregated features; don't pay for raw if not needed
- Jessica: 80% of *today's* list is answered by features; the use cases we can't articulate because we've never had the data are exactly the ones worth unlocking
- Marcus: If "raw transactions in AEP" doubles cost or timeline, should think hard
